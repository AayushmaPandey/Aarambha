# Aarambha Portal - Quick Setup & Deployment Guide

## Pre-Deployment Checklist

### 1. Database Setup
```sql
-- Execute Aarambha/App_Data/CreateDatabase.sql on SQL Server (ADMIN\SQLEXPRESS01)
-- This will:
--   - Create AarambhaDB database
--   - Create all required tables (Users, Roles, Subjects, Notes, Quizzes, etc.)
--   - Insert default roles (Teacher=1, Student=2)
--   - Create indexes for performance
```

### 2. Verify Web.config Connection String
**File:** `Aarambha/Web.config`
```xml
<connectionStrings>
  <add name="AarambhaDB" 
	   connectionString="Data Source=ADMIN\SQLEXPRESS01;Initial Catalog=AarambhaDB;Integrated Security=True" 
	   providerName="System.Data.SqlClient" />
</connectionStrings>
```
- ✅ **Server:** ADMIN\SQLEXPRESS01
- ✅ **Database:** AarambhaDB
- ✅ **Authentication:** Integrated (Windows Auth)

### 3. Create Initial Users (Manual SQL or App)
```sql
-- Insert Teacher Account (example)
INSERT INTO dbo.Users (FullName, Username, Email, PasswordHash, PasswordSalt, RoleID, IsActive)
VALUES ('Ms. Smith', 'teacher1', 'teacher@school.edu', [HASH], [SALT], 1, 1);

-- Insert Student Account (example)
INSERT INTO dbo.Users (FullName, Username, Email, PasswordHash, PasswordSalt, RoleID, IsActive)
VALUES ('John Doe', 'student1', 'john@school.edu', [HASH], [SALT], 2, 1);
```
**Note:** Hash & Salt generated by PasswordHelper when creating users via app interface.

### 4. Verify Folder Permissions
Ensure the application can write to:
- `Aarambha/Content/uploads/notes/` (for PDF uploads)
- Temp folder for file operations

## Role-Based Access Control

### Teacher (RoleID = 1)
- Can create/edit/delete subjects, notes, quizzes, announcements
- Can view all student accounts and quiz results
- Can manage notifications/messages from public contact form
- Cannot modify other teachers or system roles

### Student (RoleID = 2)
- Can view subjects and notes (with PDF attachments)
- Can take quizzes (auto-graded, attempts tracked)
- Can view own quiz results and scores
- Can view teacher announcements
- Cannot create/edit content

### Anonymous (Not Logged In)
- Can view public pages (Default, About, Subjects, Contact)
- Can submit contact message (stored in DB for teacher review)
- Cannot access Admin or Member pages (auto-redirect to Login)

## Security Implementation

### Password Hashing
- **Algorithm:** SHA-256
- **Salt:** Random CHAR(32) per user
- **Storage:** 
  - `Users.PasswordHash` = CHAR(64) (SHA-256 in hex)
  - `Users.PasswordSalt` = CHAR(32) (random salt in hex)

### SQL Injection Prevention
- All DAL classes use **parameterized SqlCommand**
- Example:
  ```csharp
  SqlCommand cmd = new SqlCommand("SELECT * FROM Users WHERE Username = @username", conn);
  cmd.Parameters.AddWithValue("@username", username);
  ```

### Authentication Flow
1. User enters credentials (Login.aspx)
2. AuthBLL.ValidateUser() called
3. UserDAL.GetByUsername() fetches user + PasswordSalt + PasswordHash
4. PasswordHelper.VerifyPassword() compares hashes
5. If valid: populate Session["UserID"], Session["RoleID"], Session["FullName"]
6. Redirect to appropriate dashboard (Admin or Member)

### Session Timeout
- Configured in Web.config: `<sessionState timeout="60" />` (60 minutes)
- Each page checks Session["UserID"] and RoleID; redirects to login if expired

## Database Schema Quick Reference

### Core Tables
- **Roles** - Teacher (ID=1), Student (ID=2)
- **Users** - FullName, Username, Email, PasswordHash, PasswordSalt, RoleID
- **Subjects** - SubjectName, Description, IconPath, IsActive
- **Notes** - Title, ContentHtml, SortOrder (per Subject)
- **Resources** - FilePath (PDF attachments for Notes)
- **Quizzes** - Title, PassMark (per Subject)
- **Questions** - QuestionText, Marks (per Quiz)
- **QuestionOptions** - OptionText, IsCorrect (per Question)
- **QuizAttempts** - Score, TotalMarks, IsPassed, AttemptedAt (per User & Quiz)
- **Announcements** - Title, Message, PostedAt (posted by Teacher)
- **ContactMessages** - Name, Email, Subject, Message, IsRead, SubmittedAt

### Key Relationships
```
Roles ←── Users ──→ Subjects
		   ↓
		QuizAttempts ──→ Quizzes ──→ Subjects
							 ↓
						 Questions
							 ↓
						 QuestionOptions

Announcements ← PostedBy (Users)
ContactMessages (no FK, public submissions)
```

## Troubleshooting

### Issue: "Cannot Connect to Database"
- **Check:** Web.config connection string matches your SQL Server instance
- **Verify:** `ADMIN\SQLEXPRESS01` is running and accessible
- **Verify:** AarambhaDB database exists (run CreateDatabase.sql)
- **Check:** Integrated Security permissions (Windows Auth)

### Issue: "Invalid Login Credentials"
- **Check:** User exists in dbo.Users table
- **Verify:** IsActive = 1 (inactive users cannot log in)
- **Verify:** PasswordHash and PasswordSalt are correctly stored (CHAR types, not VARCHAR)

### Issue: "Access Denied / Unauthorized"
- **Check:** Session["RoleID"] is set (login flow completed)
- **Verify:** RoleID matches page restrictions (Admin pages require RoleID = 1)
- **Check:** Session hasn't expired (60 minutes by default)

### Issue: "Cannot Upload PDF / File Not Saved"
- **Verify:** `Aarambha/Content/uploads/notes/` folder exists and has write permissions
- **Check:** File upload code (ManageNotes.aspx.cs) targets correct path
- **Verify:** Resource.FilePath in DB matches physical file location

### Issue: "Quiz Not Grading Correctly"
- **Verify:** QuestionOptions.IsCorrect flags are set correctly in admin
- **Check:** Quiz.PassMark property is greater than 0
- **Verify:** Student selected option maps to QuestionOption.OptionID
- **Inspect:** QuizAttempt.Score calculation in Member/Quiz.aspx.cs

## Performance Optimization Tips

1. **Add Database Indexes** (Already in CreateDatabase.sql)
   - Users (Username, Email, RoleID)
   - Notes (SubjectID)
   - Questions (QuizID)
   - QuizAttempts (UserID, QuizID)

2. **Cache Frequently Accessed Data**
   - Subjects (rarely change)
   - Roles (static)
   - Use Cache.Insert() in BLL for 1-hour TTL

3. **Pagination**
   - Implement for student list, quiz results, messages
   - Use DataSet.AsEnumerable().Skip().Take() pattern

4. **Connection Pooling**
   - Enabled by default in ADO.NET
   - Web.config connection string uses `Integrated Security=True` (pool-friendly)
